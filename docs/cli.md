# `agent-movement` command-line reference

**Status:** experimental research prototype. Every command runs synthetic, local experiments; none is production software. See the [local implementation](local-implementation.md) notes for what each experiment does and does not show.

`agent-movement` is one console script for the package's local experiments. Each subcommand is a thin dispatcher: it passes its arguments **unchanged** to the `main()` of an existing module, so that module's own parser defines the subcommand's options, `--help` text and exit codes. Each `python -m agent_movement.<module>` entry point still works on its own and behaves the same way. `python -m agent_movement` runs the same CLI without the console script.

## Install

```sh
python -m pip install -e .                                     # core: demo, peer-demo (HS256), bench, version
python -m pip install -e '.[a2a,ed25519,relocation,signing]'   # every optional extra
agent-movement version                                         # package version and which extras are installed
```

## Exit codes and optional extras

| Exit | Meaning |
|---|---|
| 0 | the command ran and its checks passed |
| 1 | a check failed (a demo assertion, a failing benchmark case, an invalid receipt) |
| 2 | usage error, or a **missing optional extra**: the CLI prints which extra is missing and the `pip install -e '.[<extra>]'` command to install it |
| 3 | `receipts verify` / `receipts timeline` only: the bundle could not be fully verified |

The CLI checks the optional extra before it runs a command (`a2a-demo` needs `a2a`, `relocate` needs `relocation`, `receipts` needs `signing`, and `peer-demo` needs `ed25519` only for `--alg Ed25519`). `--help` skips that check, except for `relocate`, whose module cannot be imported without LangGraph. The CLI is stricter than the module form in one case: `python -m agent_movement.receipts verify --trust <anchors>` without the `signing` extra still runs its structural checks and reports the signatures as unchecked (exit 3), but `agent-movement receipts verify` stops with the install hint (exit 2).

## Examples

```sh
agent-movement demo                                   # core loopback handoff, replay, denial, fencing
agent-movement peer-demo --alg Ed25519                # needs the ed25519 extra
agent-movement a2a-demo                               # needs the a2a extra
agent-movement relocate --json relocation-results.json   # needs the relocation extra
agent-movement bench verify --suite v0.1
agent-movement bench run --suite v0.1 --subset smoke --out results.jsonl
agent-movement bench report --in results.jsonl --out report.md
agent-movement bench smoke --output mobilitybench-local.jsonl   # legacy 20-case smoke
agent-movement receipts verify tests/fixtures/movement-receipts/01-valid-delegation \
    --trust tests/fixtures/movement-receipts/trust.json --now 2026-10-16T00:00:00Z
```

### `agent-movement a2a-demo`

```text
usage: agent-movement a2a-demo [-h]

Repeatable A2A v1 delegation demo: two independent OS processes plus audit join.

Run ``python -m agent_movement.a2a_demo`` after ``pip install -e '.[a2a]'``.

1. Starts the destination worker (``agent_movement.a2a_server``) as one process.
2. Fetches its Agent Card over plain HTTP (no SDK) as a wire-level smoke check.
3. Runs the origin client (``agent_movement.a2a_client``) as separate processes:
   a completed delegation (JSON-RPC, streaming), an exact retry (HTTP+JSON,
   blocking) that is answered from the receiver's idempotency ledger, a denied
   approval (task REJECTED), a request through the deprecated URN alias with a
   client-supplied contextId (profile 0.1 behaviour, still accepted), and three
   requests the A2A server refuses before any task exists: an unadvertised
   capability, an unknown schema version, and a client-supplied contextId under
   the current profile URI (this server keeps the default: server-generated).
4. Joins client-side A2A task IDs with the receiver-side audit tables.

This proves DELEGATION of one allowlisted pure task, NOT agent migration.
Authentication is absent/experimental. Synthetic data, loopback only.
This orchestrator itself uses only the standard library.

options:
  -h, --help  show this help message and exit
```

### `agent-movement bench smoke`

```text
usage: agent-movement bench smoke [-h] [--output OUTPUT] [--no-timing]

MobilityBench local smoke: reproducible synthetic *observations*, not safety proof.

Run: python -m agent_movement.mobilitybench --output /tmp/mobilitybench.jsonl
     python -m agent_movement.mobilitybench --no-timing --output a.jsonl  # byte-identical reruns
The v0.1 suite lives in mobilitybench_v01 and is reached through the
subcommands `run`, `report`, `verify` and `schedule` of this same entry point.
This uses the draft localhost experiment's application classes directly; it is
NOT A2A, authenticated networking, process migration, or real external effects.

Every case declares its expectation in a packaged fixture
(fixtures/mobilitybench-local-smoke/cases.jsonl): `pass`, `known_gap` (with the
expected fix and the observation that would show it closed), or `gap_closed`.
Each case runs in its own temporary directory and SQLite database, so the
results do not depend on case order.

options:
  -h, --help       show this help message and exit
  --output OUTPUT  JSONL destination; '-' = stdout
  --no-timing      write duration_ms as null so that two runs are byte-identical
```
